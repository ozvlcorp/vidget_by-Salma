# Публикация виджета как приватного решения МойСклад

Приватное решение не проходит модерацию и не видно в каталоге — оно ставится
**по прямой ссылке** только на ваши аккаунты.

Что уже готово в репозитории:

| Файл | Назначение |
|---|---|
| `descriptor.xml` | Дескриптор решения (загружается в кабинет разработчика) |
| `backend/` | Бэкенд Vendor API: установка/удаление, обмен `contextKey`, прокси к JSON API |
| `src/App.tsx` | Автовход: если МойСклад передал `contextKey`, вход не требуется |

---

## 1. Зарегистрировать кабинет разработчика

1. Открыть **https://apps.moysklad.ru** и войти под аккаунтом МойСклад.
2. Принять условия разработчика — появится **Кабинет разработчика**.
3. Заполнить профиль вендора (название, контакты). Оно попадёт в `appUid`.

> Приватному решению модерация не нужна, но кабинет обязателен.

## 2. Создать черновик решения

1. В кабинете: **Создать решение** → серверное приложение (ServerApplication).
2. Загрузить `descriptor.xml`, предварительно заменив в нём два адреса:
   - `<endpointBase>` — адрес бэкенда, например `https://widget-backend.oymoysklad.com`
   - `<iframe sourceUrl>` — адрес виджета, `https://salma.oymoysklad.com/`
3. После сохранения кабинет выдаст три значения — они понадобятся дальше:
   - **appId** (uuid)
   - **appUid** (вида `salma-widget.вашвендор`)
   - **Secret Key**

## 3. Задеплоить бэкенд

Бэкенд — отдельное приложение в Dokploy из этого же репозитория:

- **Build path / context**: `backend`
- **Dockerfile**: `backend/Dockerfile`
- **Домен**: тот же, что указан в `<endpointBase>` (обязательно HTTPS)
- **Volume**: примонтировать том на `/data` — иначе установка сотрётся при редеплое

Переменные окружения:

| Переменная | Значение |
|---|---|
| `MS_APP_UID` | appUid из кабинета |
| `MS_APP_ID` | appId из кабинета |
| `MS_SECRET_KEY` | Secret Key из кабинета |
| `MS_WIDGET_ORIGIN` | `https://salma.oymoysklad.com` |
| `MS_STORE_PATH` | `/data/accounts.json` (по умолчанию) |

Проверка после деплоя: `https://<домен-бэкенда>/healthz` должен вернуть
`{"ok":true,"configured":true}`. Если `configured:false` — не заданы переменные.

## 4. Указать виджету адрес бэкенда

Если домен бэкенда отличается от `https://widget-backend.oymoysklad.com`,
задать при сборке фронтенда переменную:

```
VITE_BACKEND_URL=https://<домен-бэкенда>
```

## 5. Установить решение

1. В кабинете разработчика открыть решение → **Установить** (или скопировать
   прямую ссылку установки и открыть её под нужным аккаунтом).
2. МойСклад вызовет `PUT {endpointBase}/api/moysklad/vendor/1.0/apps/{appId}/{accountId}`
   и передаст токен аккаунта — бэкенд сохранит его в `/data/accounts.json`
   и ответит `{"status":"Activated"}`.
3. Виджет появится в МойСклад отдельным разделом.

---

## Как это работает

```
МойСклад ──PUT /vendor/1.0/apps/{appId}/{accountId}──► бэкенд   (сохраняет токен аккаунта)
Виджет   ──GET /widget/session?contextKey=…─────────► бэкенд   (отдаёт сессию на 12 ч)
Виджет   ──/api/moysklad/* + сессия────────────────► бэкенд ──► api.moysklad.ru
```

Токен аккаунта хранится **только на сервере**: браузер получает лишь короткую
сессию, а бэкенд подменяет её на настоящий токен при проксировании.

## Что изменится для сотрудников

- Внутри МойСклад вход **не требуется** — виджет открывается сразу.
- Документы создаются **от имени решения**, а не конкретного сотрудника.
- Если открыть виджет по прямой ссылке (вне МойСклад), остаётся вход по личному
  логину/паролю — тогда автор документов виден.

## Проверка бэкенда локально

```bash
cd backend && npm install
MS_APP_UID=test.vendor MS_APP_ID=<uuid> MS_SECRET_KEY=secret \
MS_STORE_PATH=./accounts.json PORT=8080 npm start
curl localhost:8080/healthz
```
